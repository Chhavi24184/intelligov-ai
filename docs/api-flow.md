# API Flow

All endpoints are mounted under the base path `/api/v1`. Interactive documentation is auto-generated by FastAPI at `/docs` (Swagger UI) and `/redoc`.

## Authentication

All endpoints except `/health` expect a `Bearer` token in the `Authorization` header. In the current build, `backend/api/middleware/auth.py` implements a **JWT stub** — any bearer token is accepted. This is documented and intended to be replaced by IBM App ID OAuth 2.0 in production (see [`deployment-guide.md`](deployment-guide.md)).

Every response includes an `x-request-id` header for traceability.

## Endpoints

### `GET /health`

Returns overall service health, including the status of each IBM mock service.

**Response 200:**
```json
{
  "status": "ok",
  "services": {
    "watsonx_client": "mock-active",
    "watsonx_assistant": "mock-active",
    "vector_store": "ready",
    "knowledge_graph": "ready"
  }
}
```

---

### `POST /api/v1/citizen/profile`

Creates or updates a citizen profile.

**Request Body:**
```json
{
  "citizen_id": "priya-sharma-001",
  "name": "Priya Sharma",
  "age": 22,
  "state": "Maharashtra",
  "income": 85000,
  "education": "12th_pass",
  "caste": "OBC",
  "gender": "Female",
  "occupation": "Student",
  "documents_held": ["Aadhaar", "Income Certificate"],
  "languages": ["Hindi", "Marathi", "English"]
}
```

**Response 200:** Echoes the stored `CitizenProfile` with a generated/confirmed `citizen_id`.

---

### `GET /api/v1/citizen/{citizen_id}/twin`

Retrieves the citizen's Digital Twin.

**Response 200:**
```json
{
  "citizen_id": "priya-sharma-001",
  "life_stage": "student",
  "eligibility_cache": [ ],
  "opportunity_history": [ ],
  "preference_vector": [ ]
}
```

---

### `POST /api/v1/orchestrator/query`

Runs the full multi-agent pipeline for a citizen query. This is the primary demo endpoint.

**Request Body:**
```json
{
  "citizen_id": "priya-sharma-001",
  "query": "What scholarships am I eligible for?",
  "session_id": "auto-generated-if-omitted"
}
```

**Response 200:** A `DecisionEngineOutput` object containing intent, digital twin snapshot, eligible opportunities, ranked recommendations, explanations, and all 18 agent statuses.

This endpoint uses FastAPI `BackgroundTasks` so the frontend can immediately begin polling `/orchestrator/status/{session_id}` while agents execute.

---

### `GET /api/v1/orchestrator/status/{session_id}`

Polls live agent execution status for a running or completed orchestration session.

**Response 200:**
```json
{
  "session_id": "a1b2c3d4",
  "agents": [
    { "name": "intent_detection", "status": "COMPLETED" },
    { "name": "citizen_digital_twin", "status": "COMPLETED" },
    { "name": "opportunity_discovery", "status": "RUNNING" },
    { "name": "eligibility_verification", "status": "PENDING" }
  ]
}
```

Agent status values: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `SKIPPED`.

---

### `GET /api/v1/orchestrator/agents/pipeline`

Returns the static agent execution graph (all 18 agents and their sequencing) for rendering the Agent Workflow Visualizer.

---

### `GET /api/v1/agents`

Lists all 18 agents with their name, status (fully working / stub), and description — used for direct agent testing outside the full orchestration flow.

---

## Error Handling

All endpoints return errors in a consistent shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "citizen_id is required",
    "request_id": "a1b2c3d4"
  }
}
```

Common error codes: `VALIDATION_ERROR` (422), `NOT_FOUND` (404), `AGENT_EXECUTION_ERROR` (500), `UNAUTHORIZED` (401).
